---
name: Recipe credit semantics
description: Chef versus Mine attribution and the approved development-only metadata exception.
---

The user requires Chef / Mine credit on recipes. For Mine, the person's name
is optional. They explicitly approved saving this metadata in development.

**Why:** The user asked to identify the chef or show Mine, without requiring a
person name for Mine.

**How to apply:** Persist these credits separately from protected fixture
contents. Synthetic chef references are not verified authorship or endorsement;
keep that distinction explicit. Mine is a catalog credit label, not a private
account or a security permission.

The current shared development preview permits only narrowly scoped,
same-origin credit editing; this does not authorize public-pilot or production
write access.

**Why:** The existing preview has no per-user ownership model, while the user
approved this metadata feature only in development.

**How to apply:** Preserve the production-disabled boundary and existing content
and AI protections. A future public editing feature needs genuine owner
authorization rather than extending the development permission.
